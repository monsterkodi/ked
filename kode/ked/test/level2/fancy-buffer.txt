fancy-buffer -- unicode payload storage test

this file is plain text. everything you can read is meant to be read.
the decoration is carried in invisible codepoints, so an editor, git or a
pipe that preserves unknown codepoints preserves the decoration, and one
that strips them loses only the decoration, never the text.

tag characters   U+E0001 open, U+E0020 + ascii body, U+E007F close
vs supplement    U+E0100 + digit, base 240, first digit is byte count

section A   anchor after the run: open body close, then the run before it
            the run length is part of the body, this is the cheap form
section B   wrap around the run: open body text close
section C   variation selector supplement, no open/close at all
section D   mixed and dense

decode a line with node, tags only:
  node -e 'let o="";for(const c of process.argv[1]){const n=c.codePointAt(0);
    o += n>=0xE0020&&n<=0xE007E ? String.fromCharCode(n-0xE0000)
       : n>=0xE0000&&n<=0xE007F ? (n===0xE0001?"<":"")+(n===0xE007F?">":"")
       : (n>=0xE0100?"{"+(n-0xE0100)+"}":c)}
    console.log(o)' "$(sed -n Np this-file)"
